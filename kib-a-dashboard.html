Berikut adalah rancangan spesifikasi produknya: 📄 Product Requirements Document (PRD) Nama Produk: Aplikasi Tracking Sertipikasi Aset Tanah Pemerintah Platform: Web Application (Disarankan agar mudah diakses di kantor) 1. Ringkasan Eksekutif Aplikasi ini bertujuan untuk mendigitalisasi pemantauan progres sertifikasi aset tanah pemerintah. Sistem ini akan mengubah cara kerja manual menggunakan Excel menjadi sebuah platform terpusat yang lebih rapi, terstruktur, dan memudahkan staf dalam memantau setiap tahapan sertifikasi hingga pelaporan. 2. Target Pengguna Pengguna Utama: Staf Pengelola Aset. Motivasi & Retensi (Alasan menggunakan aplikasi): Harus siap memberikan jawaban yang cepat dan akurat setiap kali atasan meminta update terkait status aset tanah. 3. Masalah & Solusi Masalah saat ini: Data di Excel rentan berantakan, sulit melacak progres harian/mingguan secara visual, dan butuh waktu lama untuk merekap data saat atasan mendadak meminta laporan. Solusi: Sistem yang otomatis mengolah data Excel awal menjadi dashboard visual dan menyediakan checklist tahapan yang jelas. 4. Fitur Utama (Prioritas Tinggi) Berdasarkan kebutuhan fungsional harian, berikut adalah fitur inti yang harus dibangun: A. Dashboard Utama (Tampilan Pertama) Fungsi: Langsung menyajikan ringkasan visual saat aplikasi pertama kali dibuka. Isi: Total aset tanah yang sedang diproses. Grafik pie/bar berisi porsi aset di masing-masing tahap (Pengukuran, di BPN, Selesai, dll). Notifikasi/tabel kecil untuk aset yang mandek (terlalu lama di satu tahap). B. Upload & Olah Data (Import Excel) Fungsi: Memudahkan migrasi dari sistem lama. Isi: Fitur drag-and-drop file Excel (format .xls atau .xlsx). Sistem otomatis membaca kolom Excel (Nama Aset, Lokasi, Luas, dll) dan memasukkannya ke dalam database aplikasi tanpa perlu input manual satu per satu. C. Modul Tracking & Checklist per Tahap Fungsi: Inti dari pelacakan progres yang "lebih rapi". Isi: Setiap aset tanah akan memiliki kartu/baris dengan 4 checklist wajib: [ ] Tahapan Pengukuran [ ] Pendaftaran ke BPN [ ] Terbit Sertipikat [ ] Pengarsipan Catatan: Setiap kali checklist diklik, sistem otomatis mencatat tanggal penyelesaian tahapan tersebut. D. Generator Laporan Triwulan Otomatis Fungsi: Menyelamatkan waktu saat atasan meminta laporan rutin. Isi: Tombol "Unduh Laporan Triwulan" (Format PDF atau Excel yang sudah di-format rapi). Sistem memfilter otomatis aset mana saja yang mengalami pergerakan progres dalam 3 bulan terakhir. 5. Alur Pengguna (User Flow) Sederhana Buka Aplikasi ➔ 2. Lihat Dashboard (Cek status keseluruhan secara instan) ➔ 3. Cari Aset/Upload Data Baru ➔ 4. Update Checklist Progres (Misal: klik "Pendaftaran BPN Selesai") ➔ 5. Ekspor Laporan (Saat diminta atasan). Berikut adalah tambahan detail untuk draf PRD pada bagian Fitur Utama, secara khusus memperbarui dan memperluas fungsi Upload: B. Modul Upload & Sinkronisasi Data (Diperbarui) Fitur ini dibagi menjadi dua alur unggah (upload) untuk mengakomodasi siklus data dari awal hingga terbit sertipikat. 1. Upload Data Awal (Inisialisasi Data & Progres) Fungsi: Memasukkan master data tanah KIB beserta status progres terakhirnya ke dalam sistem. Mekanisme: Pengguna mengunggah Excel berisi daftar tanah. Sistem memetakan kolom standar (Nomor Berkas, Nama Aset, Lokasi, Luas, Progres Saat Ini). Data ini menjadi database dasar di dalam aplikasi. 2. Upload Data Update BPN (Sertipikat Terbit) Fungsi: Memperbarui status checklist "Terbit Sertipikat" secara massal (bulk update) berdasarkan data dari BPN, tanpa harus mengubah status satu per satu. Mekanisme Auto Look-up: Pengguna mengunggah file Excel baru yang berisi daftar sertipikat yang baru terbit dari BPN. Sistem akan membaca kolom "Nomor Berkas" pada Excel baru tersebut. Sistem melakukan pencarian otomatis (auto look-up) ke database KIB awal. Jika Nomor Berkas cocok/ditemukan, sistem akan otomatis: Mencentang/menyelesaikan tahap "Terbit Sertipikat" pada aset tersebut. Memperbarui tanggal terbit. Menambahkan nomor sertipikat baru ke profil aset tersebut. 3. Penanganan Data Tidak Valid (Error Handling / Exception Report) Fungsi: Mengantisipasi jika ada data dari Excel BPN yang tidak sinkron dengan data KIB. Mekanisme: Jika ada Nomor Berkas di Excel update yang tidak ditemukan di database awal, sistem tidak akan menolak seluruh file. Sistem akan tetap memproses data yang cocok, dan mengeluarkan pop-up atau tabel notifikasi: "Terdapat 3 Nomor Berkas yang tidak ditemukan di Data KIB. Apakah Anda ingin menambahkannya sebagai aset baru atau abaikan?" Kenapa tambahan poin nomor 3 (Error Handling) ini penting? Di lapangan, sering kali ada salah ketik (typo) nomor berkas dari pihak luar, atau ada aset yang terlewat dicatat di data awal. Fitur ini memastikan Anda tidak perlu repot mencari secara manual baris mana yang gagal di-sinkronisasi. Logika Backend: Fitur Auto Look-up Excel BPN Ini adalah bagian paling krusial dari PRD kita sebelumnya. Berikut adalah contoh implementasi logika pengolahan file Excel BPN yang diunggah menggunakan pustaka multer (untuk upload) dan xlsx (untuk membaca Excel) di Express.js: JavaScript const express = require('express'); const multer = require('multer'); const xlsx = require('xlsx'); const { PrismaClient } = require('@prisma/client'); const router = express.Router(); const prisma = new PrismaClient(); const upload = multer({ dest: 'uploads/' }); router.post('/upload/bpn', upload.single('file'), async (req, res) => { try { // 1. Baca file Excel yang diunggah const workbook = xlsx.readFile(req.file.path); const sheetName = workbook.SheetNames[0]; const rawData = xlsx.utils.sheet_to_json(workbook.Sheets[sheetName]); let successCount = 0; let notFoundRecords = []; // 2. Loop data Excel dan lakukan Auto Look-up for (const row of rawData) { // Asumsi kolom di Excel bernama "Nomor Berkas" dan "Tanggal Terbit" const noBerkas = row['Nomor Berkas']; const tglTerbit = new Date(row['Tanggal Terbit']); const noSertipikat = row['Nomor Sertipikat']; // 3. Update database jika No. Berkas ditemukan if (noBerkas) { const updateAsset = await prisma.landAsset.updateMany({ where: { no_berkas: String(noBerkas) }, data: { tgl_terbit: tglTerbit, no_sertipikat: String(noSertipikat), }, }); // 4. Catat exception handling jika berkas tidak ada di KIB if (updateAsset.count === 0) { notFoundRecords.push(noBerkas); } else { successCount++; } } } // 5. Kembalikan response ke Frontend res.json({ status: 'success', message: `Berhasil mengupdate ${successCount} aset.`, exceptions: notFoundRecords, // Frontend bisa menampilkan pop-up error handling dari array ini }); } catch (error) { res.status(500).json({ error: 'Gagal memproses file Excel BPN' }); } }); module.exports = router; Pendekatan backend ini akan membuat antarmuka frontend Anda menjadi aplikasi data yang sangat dinamis dan aman.
